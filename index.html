GdI – Assembler-Simulator

Schreiben Sie ein Assemblerprogramm für einen einfachen 8-Bit-Prozessor, übersetzen Sie es in Maschinencode und führen Sie es Schritt für Schritt oder automatisch aus. Register, Flags, Speicher und Ausgabe werden dabei laufend angezeigt.

So arbeitet der Simulator
  • Der Prozessor hat vier Register A–D, einen Stackpointer SP, einen Befehlszeiger IP und 256 Byte Speicher. Alle Werte sind 8 Bit groß (0–255).
  • Das Programm wird ab Adresse 0 in den Speicher geladen; jeder Befehl und jeder Operand belegt ein Byte. Der Stack wächst von Adresse 231 (E7) nach unten.
  • Was in die Adressen 232–255 (E8–FF) geschrieben wird, erscheint als Zeichen in der Ausgabe. HLT beendet das Programm. Alle Befehle stehen unten im Befehlssatz.

Befehlssatz und Syntax

Syntax

Jeder Befehl steht in einer eigenen Zeile. Ein Label ist optional, beginnt mit einem Buchstaben oder einem Punkt und endet mit einem Doppelpunkt. Alles nach ; ist Kommentar. 

label:  BEFEHL ziel, quelle   ; Kommentar

Konstanten

dezimal200, 200d
hexadezimal0xA4
oktal0o47
binär101b
Zeichen'A'
Zeichenkette (nur DB)"Hallo"

Operanden

RegisterA, B, C, D
StackpointerSP (nur bei MOV, ADD, SUB, CMP, INC, DEC)
Adresse aus Register[A]
… mit Offset (−16 bis +15)[D-3], [SP+2]
feste Adresse[100], [label]
Konstante (0–255)42, label

Ein Label ohne eckige Klammern steht für seine Adresse (z. B. MOV C, hello), mit eckigen Klammern für den Inhalt an dieser Adresse. In der Tabelle steht reg für ein Register, adr für eine Adresse in eckigen Klammern und konst für eine Konstante.

Bedingte Sprünge

Nach CMP x, y gelten die Vergleiche für vorzeichenlose Zahlen x und y. Befehle in einer Zeile sind gleichwertig.

BefehlBedeutung nach CMP x, yBedingung
JZ, JEx = yZ = 1
JNZ, JNEx ≠ yZ = 0
JA, JNBEx > yC = 0 und Z = 0
JNC, JAE, JNBx ≥ yC = 0
JC, JB, JNAEx < yC = 1
JNA, JBEx ≤ yC = 1 oder Z = 1
